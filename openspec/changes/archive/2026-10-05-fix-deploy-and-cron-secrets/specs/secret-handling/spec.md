# Spec Delta

## Purpose

Гарантирует, что запуск бота по расписанию получает секреты в любом поддерживаемом виде (значение или файл) и что значения секретов не попадают в вывод ошибок.

## ADDED Requirements

### Requirement: Секреты из файлов доступны запуску по расписанию
Система MUST передавать запуску бота по расписанию пути `GOOGLE_API_KEY_FILE` и `TELEGRAM_BOT_TOKEN_FILE`, заданные контейнеру, чтобы бот читал секреты из этих файлов.

#### Scenario: Секреты заданы как Swarm secrets
- **WHEN** контейнер запущен с `GOOGLE_API_KEY_FILE` и `TELEGRAM_BOT_TOKEN_FILE`, а cron запускает бота
- **THEN** бот читает ключ и токен из указанных файлов и не завершается из-за их отсутствия

#### Scenario: Секреты заданы значениями
- **WHEN** контейнер запущен с `GOOGLE_API_KEY` и `TELEGRAM_BOT_TOKEN` без `*_FILE`
- **THEN** бот использует эти значения, как и раньше

### Requirement: Значения секретов не выводятся при ошибке запуска
Система MUST NOT выводить значения ключа API и токена бота в stdout и stderr при необработанной ошибке запуска, включая текст исключения и трассировку.

#### Scenario: Ошибка Google API
- **WHEN** запрос к Google Calendar завершается ошибкой, текст которой содержит URL с ключом API
- **THEN** в выводе ошибки ключ заменён маской, а тип и причина ошибки видны

#### Scenario: Сбой запроса к Telegram
- **WHEN** запрос к Telegram завершается исключением, текст которого содержит URL с токеном бота
- **THEN** в выводе ошибки токен заменён маской

#### Scenario: Код возврата
- **WHEN** запуск завершился необработанной ошибкой
- **THEN** процесс завершается с ненулевым кодом
