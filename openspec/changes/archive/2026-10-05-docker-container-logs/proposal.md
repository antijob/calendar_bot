# Proposal

## Why

Сейчас вывод бота, запущенного cron внутри контейнера, пишется только в файл `/var/log/cron.log`. Команда `docker logs scheduler` ничего не показывает, поэтому по логам Docker нельзя понять, отработал ли бот, сколько событий найдено и почему Telegram вернул ошибку.

Кроме того, cron не передаёт заданиям переменные окружения контейнера. Проверка показала, что у PID 1 ключ `GOOGLE_API_KEY` есть, а внутри cron-задачи его нет: бот получает `API_KEY=None` и падает с `DefaultCredentialsError`. Без этого исправления логи покажут только эту ошибку, а не работу бота.

## What Changes

- Вывод (stdout и stderr) запуска `calendar_bot.py` по cron попадает в логи контейнера и виден через `docker logs`.
- Вывод скрипта не буферизуется, чтобы строки появлялись в логах сразу, а не после завершения процесса.
- Файл `/var/log/cron.log` больше не используется как единственное место для логов.
- Запуск по cron получает те же значения `GOOGLE_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_GROUP_ID`, `CALENDAR_ID`, что заданы контейнеру.

Вне объёма:
- Изменение расписания cron (остаётся раз в сутки в 00:00).
- Передача в контейнер других переменных, кроме четырёх перечисленных выше.
- Переход на модуль `logging`, уровни логов, временные метки и ротация.
- Изменение логики уведомлений и текста сообщений.

## Capabilities

### New Capabilities
- `container-logging`: вывод запусков бота доступен в логах Docker-контейнера.
- `scheduled-run-environment`: запуск бота по расписанию получает конфигурацию (переменные окружения) контейнера.

### Modified Capabilities

## Impact

- `Dockerfile`: строка cron-задания, копирование и подключение entrypoint-скрипта.
- Новый `entrypoint.sh`: записывает переменные окружения в `/app/.env` при старте контейнера.
- `docker-compose.yml`: без изменений.
- Код `calendar_bot.py` не меняется.
